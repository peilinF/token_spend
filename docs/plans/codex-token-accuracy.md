## 设计契约

### fork 识别

1. 每个文件的第一个有效 `session_meta` 头拥有该文件的 `id` 与 `forked_from_id`（包含明确的无父关系）；后续 `session_meta` 可能是复制历史，不得覆盖身份或父关系。同一 ID 可关联多个恢复文件，但这些恢复文件声明的父关系必须相同。缺父、不可读父、谱系环不猜测，保留上次结果并报告未完成。
2. 仅有显式父关系的子文件参与连续前缀匹配。比较每个候选父文件与子文件开头的 `token_count.info` 原始序列，选择最长共同前缀，并列保存全部依赖。
3. 指纹包含 `total_token_usage` / `last_token_usage` 存在性以及六字段的存在性和值：`input_tokens`、`cached_input_tokens`、`cache_write_input_tokens`、`output_tokens`、`reasoning_output_tokens`、`total_tokens`。缺失与零有别，忽略外层时间戳、rate_limits、其他内容。
4. 第一条不匹配即没有可证实复制前缀，沿用 v3 首条 last 策略；分叉后不继续去掉偶然相同请求。嵌套 fork 与父原始序列比较，不能与父贡献行比较。
5. 复制前缀不写 token 贡献，但仍更新额度与原始累计基线；基线用最后有效 total 而非 last，之后差值计新增。

### 持久化、扫描、显示

- Codable fork 状态保存父 ID、全部父路径/身份/签名、匹配数、子前缀结束字节、规范化前缀 SHA-256、原始基线和游标，与贡献行同事务提交。重启先验证父依赖，不能只因子签名没变跳过。
- 正常父追加不重建子贡献；替换、截断、原地改写要验证并重建受影响父子。mtime 变化但大小相同不能简单当 touch。
- 每次固定开始时文件大小，仅读至该边界内完整换行。追加尾部下次处理；替换/截断放弃本次结果。
- 精简说明「不含缓存的输入 + 输出」，全量说明「含缓存的输入 + 输出」，token 数量不等同费用/额度。
- 非零 cache_write 如导致桶关系无法成立要报异常，不得静默截零并声称准确；本次不扩展计费解释。

## 实施步骤

1. 测试存储路径注入，默认真实路径不变。所有测试仅使用临时 DB 与脱敏夹具；先加入复现 fork 重复的失败测试。保留独立 Swift 验证方式，不安装 XCTest 或依赖。
2. 实现索引、匹配、增量持久状态，保持已有重复快照/完整行/累计重置逻辑。父 + 多子总量必须等于父真实量 + 各子新增。
3. 新增 source 原子替换接口，同时替换指定来源贡献行与指定统计元数据。parser 升 v4：先 SQLite backup API 备份（0600，失败中止），再完整枚举/固定扫描/暂存全部汇总与游标，全部成功后一事务替换 Codex 贡献、游标、基线、fork 状态和版本4。失败不改旧行/游标/版本；保留 rate_limits、其他来源/偏好。重算保持旧值并显示「Codex 统计正在重算」。
4. reconcile 与 refresh 共用进程内锁和按数据库路径区分的 owner-only `flock` 文件锁；锁覆盖整个来源刷新/清理。目录缺失/枚举出错/不完整不删；贡献 key 用最后一个 `|` 分隔日期。删除仍被依赖的父文件时，先在同一锁内重选剩余同 ID 恢复候选；父完全缺失时保留旧贡献和游标并显示未完成。确认删除时贡献和游标/fork 元数据同事务清理。
5. 新增 `--audit-codex [报告路径]`，无路径输出 JSON。主程序早分流，直接只读 SQLite 单读事务捕获 rows/meta，不初始化 UsageStore.shared，不 refresh、不 Cursor 网络。按已提交 offset 独立计算（不得复用生产贡献计算函数），报告时间/时区/版本、每日各桶/lean/full、fork 前缀/新增、DB 差值、未解析尾部/异常。退出0一致且无阻塞，1不一致，2不可完成。
